# 이미지 복구 및 저장소 개선

## 반영 내역

- 발행 글 6개와 초안 2개의 이미지 주소 131개를 조사했습니다.
- 확보 가능한 124개 주소를 현재 Cloudinary 저장소로 복사하고 다운로드와 크기를 검증했습니다. 동일한 원본 파일은 중복 업로드하지 않았습니다.
- 8개 글에서 사진 주소만 변경했습니다. 본문, 캡션, 순서, 배치, 발행 상태는 유지했습니다.
- 원본 파일과 변경 전 Firestore 문서는 로컬 `.image-migration/2026-10-19/`에 보관했습니다. 초안이 포함되므로 Git에 올리지 않습니다.
- 각 글의 변경 전후 스냅샷도 비공개 편집 이력에 추가했습니다.
- 새 업로드는 Cloudinary만 사용하며 실패를 ImgBB로 우회하지 않습니다. Netlify의 클라이언트 업로드 설정도 추가했습니다.
- 화면 크기에 맞는 이미지 전송, 지연 로딩, 로딩 실패 표시와 재시도, 인스펙터의 개별 사진 교체를 적용했습니다.
- 운영 검수에서 오래된 서비스 워커가 삭제된 기사 JS 파일을 요청하는 문제도 재현했습니다. 앱 셸과 페이지 파일을 같은 버전으로 함께 캐시하며, 오류 시 인증·초안 데이터는 유지한 채 앱 캐시만 갱신합니다. 작성 중에는 자동 새로고침하지 않습니다.

## 유지관리

`scripts/image-maintenance.mjs`는 인증된 Firebase CLI의 `lib/auth.js` 경로를 `FIREBASE_CLI_AUTH_MODULE`로 받습니다. 인증 토큰은 기록하지 않습니다. 대상 프로젝트는 `uarchive-8e437`로 제한되어 있습니다. Node 22 이상을 사용합니다.

- `audit <새 백업 폴더>`: 문서 백업과 이미지 다운로드. 기존 폴더 재개는 `--resume`을 명시합니다.
- `recheck <백업 폴더>`: 실패한 원본만 재확인합니다. 현재 문서는 변경하지 않습니다.
- `migrate <백업 폴더>`: 원본을 육안 검수한 뒤 `CONFIRM_IMAGE_REVIEW=1`을 명시해야 업로드합니다. 알려진 오류 그림은 거부합니다. 업로드 매핑이 있으면 재사용합니다.
- `apply <백업 폴더>`: `APPLY_IMAGE_MIGRATION=uarchive-8e437`을 명시해야 글 주소를 변경합니다. 동시 편집을 검사하고 조건부 일괄 쓰기 및 사후 검증을 수행합니다. 실제 반영은 이미 완료되었으므로 기존 폴더에 재실행하지 않습니다.

복구 검토 시 `articles-backup.json`과 `applied.json`을 비교합니다. 오래된 문서 전체를 덮어쓰면 새 편집이나 조회 수를 잃을 수 있으므로, 되돌릴 경우 반드시 최신 문서를 백업하고 변경된 이미지 필드만 검토합니다. 편집 이력에서 복원할 때도 이후의 본문 편집 유무를 먼저 확인합니다.

Cloudinary API secret은 클라이언트에 넣지 않습니다. 공개 unsigned preset은 이미지 유형·용량·저장 폴더 제한을 유지하고 사용량을 점검합니다. 추후 서명 업로드를 도입하면 직원 인증과 서버 측 제한을 함께 적용해야 합니다. Cloudflare로 사이트 전체를 이전할 필요는 없습니다.
