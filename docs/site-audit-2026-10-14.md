# U# 사이트 검수 (2026-10-14)

## 범위와 검증 한계

React 라우팅, Firebase 로그인·권한, 홈·About·서재·게시물·관리자 코드,
TipTap 에디터·초안·인스펙터·갤러리, PWA와 배포 설정을 검토했다.
실제 브라우저에서는 비로그인 상태로 홈 → About → 서재 → 홈 → 게시물 이동,
게시물의 슬라이드·캡션·이미지 확대, 390×844 모바일 표시를 확인했다.
운영 데이터에 테스트 글을 발행하거나 관리자 설정을 변경하지 않았다.
직원 컴퓨터의 Chrome/ChatGPT 로그인 완료, 인증된 에디터·관리자 화면,
Firebase 서버 보안 규칙, Netlify 배포 완료는 이번 검수에서 직접 확인하지 못했다.
접근성 인증이나 Lighthouse 실측 점수는 산출하지 않았다.

Chrome 오류는 실제 브라우저 로그에서 ScrollToTop을 원인으로 지목했다.
기존 캐시 원인 설명만으로는 이 증상을 설명할 수 없다. 일부 브라우저의
scrollTo가 Promise를 반환하므로 이를 React 효과의 정리 함수로 반환하면 안 된다.
참고: https://developer.mozilla.org/en-US/docs/Web/API/Window/scrollTo

## 권장 개선 순서

1. **P1: 구글 로그인 운영 도메인 검증.** Netlify에서 Firebase redirect 로그인은
   인증 도메인과 사이트 도메인이 다를 때 저장소 제한에 영향을 받을 수 있다.
   인증 도메인·허용 도메인·OAuth 리디렉션 주소와 프록시 구성을 실제 배포 설정과
   대조하고 Chrome에서 로그인 완료까지 검증한다. 현재 코드 변경만으로 해결을 단정하지 않는다.
   참고: https://firebase.google.com/docs/auth/web/redirect-best-practices
2. **P1: 데이터 보호.** 발행 번호는 현재 최고 번호 조회 후 별도로 저장하므로
   서로 다른 직원이 동시에 발행하면 같은 번호가 생길 수 있다 (`useDrafts.js`).
   서버 측 트랜잭션 기반 번호 배정을 도입한다. 앱 내부 링크 이동에도 저장 전 이탈 방지,
   로컬 초안 복구와 짧은 자동 저장 주기를 추가한다. 서버 보안 규칙도 별도 검수한다.
3. **P2: 실제 기능 연결.** 홈의 SubscribeBand JOIN 버튼에 처리 코드가 없다.
   뉴스레터 서비스 연결 전에는 가입 가능하다고 오해하는 UI를 정리한다.
   Terms/Privacy 링크와 Network 링크도 현재 `#`로 연결되는 경우가 있다.
   실제 문서·주소를 등록한다. 저장 성공·실패 알림은 여러 페이지에서 콘솔에만 출력되므로
   공통 화면 알림으로 연결한다.
4. **P2: 모바일 탐색과 접근성.** 상단 About/My U# 메뉴는 작은 화면에서 사라지고
   대체 메뉴가 없다. 모바일 메뉴를 추가하고, 작은 슬라이드 점·화살표의 터치 영역을
   확대한다. 이미지 확대창의 포커스 이동·가두기·복귀도 보완한다.
5. **P2: 편집·읽기 일치.** 슬라이드 이동 버튼은 게시물 화면에서만 동작한다.
   런타임을 공유하고 인스펙터 미리보기에서도 같은 동작을 제공한다.
   `blocks.css`와 ViewPage의 중복 스타일도 통합해 다음 수정에서 화면 간 차이를 방지한다.
6. **P2: 초기 로딩.** 현재 빌드의 주 JavaScript 파일은 약 1.38MB,
   gzip 약 414KB다. 에디터·관리자 페이지를 필요할 때 불러오도록 분리하고,
   홈의 보이지 않는 순위 조회와 이미지 로딩을 줄인다. 실제 기기에서 변경 전후를 측정한다.
7. **P3: 운영 문서·관측.** README는 기본 Vite 템플릿이다. Firebase 인덱스·규칙,
   Netlify 배포·복구와 직원용 편집 흐름을 문서화한다. 오류 발생 경로·브라우저·빌드 버전을
   수집하면 자동 새로고침에 의존하지 않고 원인을 추적할 수 있다.
   개발 모드에서 TipTap의 flushSync 관련 경고도 관측했다. 화면 중단은 재현되지 않았지만
   에디터 생성·해제 시점을 별도로 점검할 필요가 있다.

## 검증 결과

- ESLint 및 운영 빌드 통과. 대형 번들과 오래된 Browserslist 데이터 경고는 남아 있다.
- 변경한 UI 파일의 기계적 디자인 검사에서 검출 항목 없음. 접근성 인증을 뜻하지 않는다.
- 초안 회귀 테스트 7개 통과: 저장 실패 시간, 저장 중 편집, 이미지 전용 문서,
  오래된 로딩 결과, 에디터 준비, 동시 쓰기, 발행 중 편집 후 화면 유지.
  실행: `node --experimental-vm-modules --test tests/useDrafts.test.mjs`.
  React 훅·Firebase는 모킹했으므로 운영 계정의 실제 저장 검증을 대체하지 않는다.
- 모바일 게시물의 가로 넘침 없음, 슬라이드 폭과 표시 영역 동일(343px),
  다음 장 번호와 이미지별 캡션 표시 확인. 이미지 확대·닫기도 확인.

## 유지할 장점

에디션 번호 중심 아카이브, 본문과 이미지별 캡션, 공개 글 수정 시 별도 초안 생성,
테마 변수, 이미지 업로드 진행 표시, 권한 확인 로딩 화면은 유지할 만한 기반이다.
인스펙터는 데스크톱에서 상단 80px 기준 fixed로 구현되어 있다.
이번에는 인증된 실제 화면에서 스크롤 동작을 검증하지 않았으므로 완료 판정은 유보한다.
